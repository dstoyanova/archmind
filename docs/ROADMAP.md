# ArchMind — Development Roadmap

The roadmap is organised around delivering usable capabilities rather than implementing infrastructure for its own sake.

## Phase 1 — Foundation

- [ ] Initialise monorepo and development tooling.
- [ ] Configure linting, formatting and testing.
- [ ] Set up database and initial schema.
- [ ] Implement authentication and workspaces.
- [ ] Establish application structure and CI.

**Outcome:** A working development foundation.

## Phase 2 — Code Intelligence

- [ ] Implement GitHub App integration.
- [ ] Retrieve repository source code.
- [ ] Implement TypeScript source analysis.
- [ ] Extract symbols and dependencies.
- [ ] Build the initial architecture model.

**Outcome:** ArchMind can understand a TypeScript repository.

## Phase 3 — Architecture Explorer

- [ ] Persist architecture snapshots.
- [ ] Implement component and dependency APIs.
- [ ] Build interactive architecture visualisation.
- [ ] Add component and dependency exploration.

**Outcome:** Users can explore their software architecture.

## Phase 4 — AI Assistant

- [ ] Implement architecture context retrieval.
- [ ] Build the initial architecture assistant.
- [ ] Add evidence-backed answers.
- [ ] Introduce agent execution tracing.

**Outcome:** Users can ask questions about their architecture.

## Phase 5 — Governance

- [ ] Define architecture rule model.
- [ ] Implement deterministic rule evaluation.
- [ ] Generate architectural findings.
- [ ] Add governance explanations and recommendations.

**Outcome:** Users can identify and understand architectural risks.

## Phase 6 — Beta

- [ ] Improve usability and onboarding.
- [ ] Add analysis history and comparisons.
- [ ] Implement security and operational monitoring.
- [ ] Validate with early engineering teams.

**Outcome:** A usable MVP ready for real-world feedback.
